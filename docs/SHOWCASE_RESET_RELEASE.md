# Showcase reset release and recovery

The reset is scoped to private event `e6bd40cf-4107-43ea-8c87-057dc38ef31b`, public ID `9c25613c-6543-4d6c-84cf-97ba49017509`, and requires both the synthetic marker and a current authenticated Organizer grant. The historical baseline is installed privately from the owner-held backup, not committed. Reset replaces only the display state of this event, advances its event, match and game-progress revisions, and retains score decisions and audit history. It fails closed if the roster/bracket structure has changed. Old clients must refresh; never automatically resend an uncertain reset. Spectator/TV refresh through the existing event-publication trigger.

The installer reads only the SHA-256-pinned historical backup and writes a mode-600, event-scoped SQL fragment outside the checkout. It validates identity, counts, pairings and references; it does not include Auth records, credentials, registration links or unrelated events. The fixture is private and append-only in `fftt_private.showcase_reset_baseline`. The reviewed migration checks the exact installed V6 function fingerprints before replacing them with versions that preserve numeric progress watermarks for this one showcase. Production release must apply the reviewed migration and generated fixture as one protected, target-pinned installation, verify that the baseline is present without returning its contents, and then deploy Staff with its existing Functions. Never put the fixture fragment in Git, CI logs, or a publicly served bundle.

If reset cannot be confirmed, do not automatically send it again. Refresh and inspect the showcase; the same actor and request ID return the existing reset decision without another reset. For recovery, retain the append-only audit and score receipts. Releasing prior Staff code hides the control but does not undo a reset; database rollback or restoration requires separate review.
