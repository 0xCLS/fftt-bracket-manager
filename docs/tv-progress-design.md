# TV match progress: future public projection

The current score-entry workflow submits a complete result as a single authorized operation. The public tournament projection includes result scores but has no established interim-game publication or individual completion timestamp. The TV therefore displays “Game scores pending” for active matches and labels the structurally ordered result list “Completed Results.” It does not infer 0–0, publish a tournament record from names, or use the event update time as a match completion time.

If live game progress is later authorized, keep it separate from the authoritative result. A server-owned, event-scoped progress projection could expose only a match's public identifier, ordered completed game score pairs, format, and a server revision. Staff writes would require existing event-scoped authorization and server validation of each finished game against that match's format; the public endpoint would be anonymous and read-only, gated by event publication. It must never create a result, choose a winner, change eligibility, or advance a bracket. Final submission remains the sole authority and should atomically supersede or clear progress. Corrections, unpublishing, reassignment and event deletion must invalidate the projection; missing, inconsistent, or stale progress must display as unavailable. The public allowlist must reject unexpected fields and avoid participant contact details, ratings and credentials.

This is a design boundary, not an implemented data contract or authorization to deploy one. Before implementing it, review the scoring transaction and access policies, define concurrency and cleanup semantics, and add event-isolation, anonymous-read, privacy, validation, stale-data and no-bracket-advancement tests. A server-assigned match completion timestamp could separately provide genuine result chronology, subject to the same review and release safeguards.

## Implemented TV behavior

The anonymous TV page rotates Match Center (30 seconds), Completed Results (12 seconds), and available Championship and Consolation bracket presentations (18 seconds per segment). Arrow keys navigate, Space pauses or resumes, and keys 1–4 select a presentation; controls are also available in the focusable overlay. Public feed refresh, invalid-response rejection, stale labels, and expiry use the existing shared reader. A pause affects rotation only. The result tally is calculated only from a completed result whose game scores pass the shared match-format validation; older results lacking format metadata retain their recorded score text without a calculated tally. Bracket windows limit the number of visible rounds and matches.

Run `node --test tests/e2e/tv_presentation.test.mjs` with Chrome and the installed e2e dependencies for fictional browser coverage; set `TV_SCREENSHOTS` to an output directory to regenerate the eight viewport captures. The public display and isolation tests remain independent of production services.
