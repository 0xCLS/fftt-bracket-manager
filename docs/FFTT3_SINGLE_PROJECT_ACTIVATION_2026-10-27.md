## Launch implementation sequence (single coordinated release)
1. **Full names:** For every new player, default to the **sanitized full name supplied by registration**, or a full first/last name for manual/walk-in check-in. Don't silently abbreviate to first + last initial. Legacy recorded fictional players stay unchanged. No contact data in roster, score APIs, exports or public projection.
2. **In-place, non-destructive DB release:** Use the source-pinned **candidate generator** `tools/release/build_single_project_upgrade.py`, NOT the fresh-database real-only generator, and do not run it against the hosted project until an approved release. Confirm the four old events and private histories persist, new events are clearly `synthetic_only=false`, event mode is immutable, Auth grants and lifecycle/score rules still apply, and staging fiction cannot enable a real Google source.
3. **Independent acceptance:** Run a realistic populated PostgreSQL clone/rehearsal, restoration test, genuine signed GoTrue organizer/scorekeeper/outsider access, revoked-role/cross-event denial, simultaneous scores, consent/public-projection checks and both desktop/mobile/TV UI flows. A passing in-process or JWT-stub simulation is helpful but **not the final gate**.
4. **Backup and hold point:** Privately snapshot current schema, auth/staff mapping, all fictional result/receipt history and configured registration-source metadata, restore on a disposable instance, compare counts/fingerprints and record a tested rollback procedure. Supabase Free may not provide managed daily backups. Obtain a focused organizer approval for the exact migration/cutover plan and preflight.
5. **Controlled database migration:** During an agreed maintenance window, apply only the reviewed in-place SQL to the existing project. Requery constraint, event counts, staff grants, score decisions and audit counts; confirm 0 unintended changes and no public output. Halt and restore if any check fails. Do not merge PR #19 by default.
6. **Create the FFTT3 real event** (separate from synthetic rehearsal event). Add only intended Organizer and scorekeepers; sign in independently; check correct event and audit trail. Use its **real UUID** as the sole Cloudflare Staff `REGISTRATION_EVENT_IDS` allowlist entry.
7. **Enable read-only Google registration for that event:** Preserve protected `GOOGLE_SA_EMAIL` and `GOOGLE_SA_PRIVATE_KEY`, set a new private `REGISTRATION_REF_SECRET` (≥32 random chars), and switch **Staff** `REGISTRATION_GOOGLE_MODE=enabled` only after the event/allowlist/privileges are verified. Verify `REGISTRATION_ENABLED`, Staff origin and restricted Google Sheet Viewer sharing. Do not put any secret or sheet answers into GitHub, chat, client JavaScript, spectator Pages or audit logs. Ensure no real sheet is shared with the separate Outreach Tracker.
8. **Organizer acceptance:** Staff → Players → Registration settings → Google Sheet → inspect/test `Form Responses 1` → review the heading mapping → save and enable → **Load registrations**, reconcile duplicate responses to unique players, review provisional level suggestions, perform controlled test check-ins. Verify contacts/answers are stripped; rollback by disabling source or switching mode to `diagnostic` on any incident. **Avoid importing actual responses until authorized**. Checking in intentionally stores only the resulting name/level/reference and audit, not entire answer rows.
9. **Public and event-day acceptance:** Display full first/last names publicly only after confirming participant notice/organizer publication policy. Never expose contact details, sign-up answers, ratings, private IDs or staff routes. Test scorekeepers on separate devices, table contention, bracket, consolation, doubles, TV stale/reconnect, results, backups and paper scoring fallback. Only then approve public visibility. Complete November 8 onsite rehearsal and November 22 final readiness.
