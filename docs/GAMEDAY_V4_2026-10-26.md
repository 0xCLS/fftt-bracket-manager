# Game-day V4 — configurable formats, registration check-in, event management, UI polish (October 26, 2026)

_Status: **implemented and tested locally and in CI on the unmerged integration branch (PR #19). Not deployed. No hosted migration applied. No real FFTT3 data used.** Applying the SQL and deploying are separate owner decisions (section 7)._

## 1. What changed

| Area | Result |
| --- | --- |
| **Match formats** | Best of 1 or Best of 3, games to 11 or 21, always won by two (exactly two once past the target). Defaults: Championship Bo3/11, Championship Final Bo3/11, Consolation Bo1/21, Consolation Final Bo1/21, Mixed-Skill Doubles Finale Bo3/11. **Best of 5 is no longer selectable.** Event-level configuration (Overview → Match formats), per-match organizer override before a result, lock once a result exists. The same rules reach the database, the scoring engine, the Scorekeeper dialog, the Organizer screens, corrections, CSV/text exports, the spectator page and the TV board. |
| **Historical Best of 5** | Matches built before V4 carry **no stamp**; their format resolves from the legacy rule (regular Bo3, championship final Bo5, games to 11). V4 never rewrites a match, score, winner or event row. Historical results stay correctable under their own format, and are labelled "historical" everywhere. |
| **Registration & check-in** | Organizer-only screen: read-only registration list, search, filters, one-click and bulk check-in, duplicate detection with merge ("same person") or dismiss ("different people"), roster-name matching and linking, manual walk-ins, suggested provisional Levels 1–5 with reasons, explicit organizer confirmation. A private-CSV fallback runs in the browser only. See [REGISTRATION_INTEGRATION_2026-10-26.md](REGISTRATION_INTEGRATION_2026-10-26.md). |
| **Event management** | Filter chips (Active, Draft, Completed, Archived, All) with counts; Archive and **Restore** (to the state it came from, never re-publishing); **permanent deletion only for an empty draft**, by a platform organizer, with the exact name typed, with the audit trail preserved in an append-only tombstone. Sign-in no longer asks for a technical event ID: after the password (or code) proof the person's own events are listed **by name**. |
| **UI/UX polish** | Consistent spacing/typography/controls, labelled event switcher, skip link, focus return from dialogs, responsive tables that become labelled cards, bottom-sheet dialogs and large score inputs on phones, tablet sidebar, loading/empty/error states, contrast fixes, draft/selection/scroll/focus preservation across background refreshes. Charcoal-and-pastel direction, emblem and "Developed by Chris Smith" retained. |
| **Reliability** | A score prepared under an old format is refused locally; one already in flight is refused by the database as a **definite** validation error ("NOTHING was recorded"); a double tap sends once; registrations are dropped with every other private view; the Single-game (Best of 1) score no longer trips the legacy intent validator (found and fixed by these tests). |

## 3. Migration review notes (what the SQL does and does not do)

* **Replaced functions** (same signature, grants kept): `submit_match_result_v1` (format lookup + shared validator; the V2 wrapper, receipts and decision ledger are untouched), `v3_create_bracket` (stamps formats), `correct_result_v3`, `record_doubles_result_v3`, `set_lifecycle_v3` (remembers where an archive came from), `organizer_snapshot_v3` (adds `formats`, per-match `best_of/points/format_legacy`, roster provenance), `v3_refresh_public` and the public view (formats added to the allowlist), `reject_audit_mutation` (see below).
* **New:** formats RPCs, `fftt_matchdesk_v2` (v1 is untouched), registration check-in and rating confirmation, restore and delete, `fftt_my_events_v4`, tables `registration_links` and `deleted_events` (RLS on, no API grants).
* **No contact column exists or is added.** Names that look like an e-mail or phone are refused (as in V3). Registration references are opaque HMAC tokens made by the adapter.
* **Audit stays append-only.** Deleting an empty draft event must remove its audit rows (they cascade). `reject_audit_mutation` now permits that single case only when a transaction-local marker equals the event id **and** a tombstone holding a full copy of those rows already exists. The tests prove the marker alone, a direct delete and a superuser delete are still refused.
* **Deletion eligibility (server-enforced, not UI):** `draft`, never built, no players, brackets, matches, doubles, results or decisions, not public; organizer of the event **and** platform organizer; typed name must match exactly.
* **Replay safety:** nothing here re-executes on existing data; legacy events keep working because unstamped matches resolve from the legacy columns.

## 4. Compatibility and deployment order

V4 changes the organizer snapshot and adds the formats Match Desk, so **the V4 SQL and the new staff/spectator bundles must go live together** (a short window). Each side fails closed rather than showing wrong data: an old staff app against V4 refuses the new snapshot; a new staff app against V3 cannot list events. The spectator parser accepts servers with or without the format fields.

## 6. Not done / open (stated plainly)

* **No live Google connection.** The adapter is complete and tested against a mocked Google; connecting a real sheet needs the owner steps in the registration document. Staging deliberately runs it on **synthetic sample data only**.
* **Production cutover, real participants, hosted migration, deployment: not performed and not authorized.**
* **Physical-device rehearsal** (phones/tablet/TV, venue network) is still outstanding.
* **Deferred, not implemented (decision recorded):** three-match guarantee, Swiss, double elimination, extra divisions. The Championship + Consolation structure is unchanged.
* The suggested-level logic was **corrected on October 26 against the approved FFTT3 form's exact question headings and answer choices** (the public blank form was read; no response row was). The original version ignored the descriptive rally answers and let incidental words in the profile descriptions raise ratings; see the registration document for the corrected rules. A second calibration the same day removed the hard one-level limit around the self-chosen profile (a strongly contradicted profile can now be out-voted, with an explicit organizer-review warning and lower confidence; an automatic Level 5 still needs competitive evidence). Suggestions remain provisional and need organizer confirmation.
